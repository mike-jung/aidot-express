# Upgrade from 1.42.1 to 1.43.0

Use a maintenance window. This release changes authentication state and Public
packaging, so a mixed-version rolling deployment is not supported by this upgrade.

1. Stop the supervisor/Electron application and back up the database, workspace,
   environment file and encryption-key material. Keep a copy of the original release.
2. Apply the supplied patch with its hash-verifying script, or unpack the Full source
   into a new directory and reconnect the existing external configuration/workspace.
   A patch conflict means a local file differs from the reviewed baseline; reconcile
   that file before applying. Do not overwrite local changes blindly.
3. Replace `CORS_ORIGIN=*` with an empty value for same-origin use or a comma-separated
   list of exact frontend origins. Confirm cookie security, proxy trust and listener
   settings in [Security operations](SECURITY_OPERATIONS.md).
4. Install locked dependencies: `npm ci`, then `cd admin-client` and `npm ci`.
   Native SQLite and Argon2 builds may require the platform's build tools.
5. Build the intended console: `npm run build:admin:full` for a Full source installation;
   use `npm run build:admin` before Public export/installer packaging. In an exported
   Public source tree, `npm start` builds the Public console into the runtime directory.
6. Start one instance first. Migration `009_user_token_version` adds account and
   refresh issuance versions for users; `014_admin_token_version` does the same for
   console accounts. Both MariaDB and SQLite variants are supplied. Confirm successful
   migration before bringing other instances back.
7. Sign in and complete any required initial-password change. Password changes and
   account updates invalidate previous sessions. Verify login, refresh, permissions,
   control status and one representative business transaction.

The original public GitHub tree and the attached Full archive had different version
numbers during review. Apply this patch to the attached 1.42.1 Full baseline; do not
apply it blindly to a different public or private commit.

Uploaded HTML/documents now download with an isolated CSP at both upload URL aliases.
If the business application used uploads as executable web pages, move that content
to a separately trusted hosting path. Deep JSON input beyond the supported security
depth is rejected; check unusually nested request schemas during upgrade.

## Packaging changes

Full and Public console bundles now live in separate output directories. A stale or
wrong-edition bundle stops packaging. The obsolete duplicate `public/assets` bundle
was removed; the console's runtime source is `admin-client/dist`.

`sync:public` now creates a reviewable local export by default. A remote update
requires `npm run sync:public -- --push`; it preserves the existing main history and
uses a normal push. `npm run all` retains its explicitly publishing behavior.
Public and Full repository settings must be distinct. Enterprise release uploads
require `--to-full --allow-full` and a repository whose API metadata confirms it is
private. Direct `electron-builder` usage is rejected unless edition configuration
has been generated by the supported build script.

## Rollback

Do not run old and new authentication implementations against the same database
concurrently. Stop the new application, restore the backed-up application/database
pair and configuration, then restart. Restoring source alone does not reverse a
migration or restore prior account versions. Operational data created after the
backup needs an explicit reconciliation plan.
